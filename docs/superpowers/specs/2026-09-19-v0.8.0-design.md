# v0.8.0: framework-neutral middleware and a smaller core

Date: 2026-09-19
Status: approved in discussion, awaiting spec review
Baseline: master at v0.7.1 (0c6d49b)

## Goal

Make the library adoptable outside Gin and outside a specific SaaS shape:

- **PR-A.** The middleware is implemented once on `net/http`; Gin becomes a
  thin adapter in its own Go module so core consumers stop pulling Gin.
- **PR-B.** Plans, limits, and auth stubs leave the core. What remains is
  tenant identity, isolation, migrations, resolution, hooks, and connections.

Both PRs merge before one release. Tags: `v0.8.0` and `middleware/gin/v0.8.0`.

## Non-goals

- Row-level-security mode, multiple databases, custom-domain resolution.
- Any change to migration semantics, hooks, metadata storage, or the
  pooler-safe `tenant.Conn`.
- A v1.0 API freeze. That is the release after this one.

## Order

PR-A first, then PR-B. The limits middleware must be rewritten on `net/http`
anyway, and the Gin nested module makes PR-B's Gin edits trivial.

## PR-A: middleware on net/http, Gin as an adapter

### Package `middleware/httpmw`

```go
package httpmw

type Config struct {
    // SkipPaths are path prefixes that bypass ResolveTenant (and therefore
    // everything downstream that needs a tenant), e.g. "/health".
    SkipPaths []string
    // ErrorHandler writes the response for a tenant error. Default: JSON
    // {"error":{"code","message"},"tenant_id"?} with the status mapping
    // below.
    ErrorHandler func(w http.ResponseWriter, r *http.Request, err error)
}

type Middleware struct { /* manager, resolver, logger, config */ }

func New(manager tenant.Manager, resolver tenant.Resolver, logger *zap.Logger, cfg Config) *Middleware

func (m *Middleware) ResolveTenant() func(http.Handler) http.Handler
func (m *Middleware) ValidateTenant() func(http.Handler) http.Handler
func (m *Middleware) EnforceLimits() func(http.Handler) http.Handler   // PR-B changes its input, see below
func (m *Middleware) SetTenantDB() func(http.Handler) http.Handler
func (m *Middleware) LogAccess() func(http.Handler) http.Handler

// Chain applies middlewares in order: Chain(h, a, b) == a(b(h)).
func Chain(h http.Handler, mws ...func(http.Handler) http.Handler) http.Handler
// Standard is ResolveTenant, ValidateTenant, EnforceLimits, SetTenantDB.
func (m *Middleware) Standard() func(http.Handler) http.Handler
```

Behaviour is identical to today's Gin middleware except:

- Everything downstream reads from `r.Context()` using the existing
  `tenant.GetTenantFromContext`, `GetTenantIDFromContext`,
  `GetTenantConnFromContext`. `ResolveTenant` puts the full `*tenant.Tenant`
  in context too (`tenant.WithTenantObject` / `TenantObjectFromContext`).
- `LogAccess` reads the user id with `tenant.UserIDFromContext(ctx)`; apps
  set it with `tenant.WithUserID(ctx, id)`. Client IP defaults to
  `RemoteAddrIP(r)` (the host part of `r.RemoteAddr`), which the client
  cannot spoof; `Config.ClientIP` overrides this, and `ForwardedClientIP`
  (first `X-Forwarded-For` entry, else `X-Real-IP`, else `RemoteAddr`,
  ignoring header values that don't parse as an IP) is provided for apps
  behind a trusted reverse proxy that sets those headers.
- `RequireAdmin` and `Config.RequireAuthentication` are not ported. Access
  and role checks belong to the application's auth layer.
- `EnforceLimits` stores the checked limits in context under
  `tenant.ContextKeyPlanLimits` for handlers that want them.

Status mapping (`TENANT_INVALID_STATUS` moves from 500 to 403;
`USER_NOT_AUTHENTICATED` and `ADMIN_REQUIRED` are gone with their features):
`TENANT_NOT_FOUND` 404; `TENANT_SUSPENDED`, `TENANT_CANCELLED`,
`TENANT_PENDING`, `TENANT_INVALID_STATUS` 403; `PLAN_LIMIT_EXCEEDED` 402;
`TENANT_CONTEXT_MISSING`, `DATABASE_ERROR`, `LIMIT_CHECK_FAILED` and anything
else 500; `*tenant.ValidationError` 400.

### Package `middleware/gin` (nested module)

Module path `github.com/alexalmadav/go-multitenant/middleware/gin`, its own
`go.mod` requiring the core. Public API is preserved:

- `Config{SkipPaths, ErrorHandler func(*gin.Context, error)}` (no
  `RequireAuthentication`).
- `NewMiddleware(manager, resolver, logger, Config) *Middleware` and the
  methods `ResolveTenant`, `ValidateTenant`, `EnforceLimits`, `SetTenantDB`,
  `LogAccess` returning `gin.HandlerFunc`. `RequireAdmin` is removed.
- Gin context keys `tenant`, `tenant_id`, `tenant_object`, `tenant_conn`,
  `plan_limits` are still set, and `GetTenantFromContext(c)`,
  `GetTenantFromGinContext(c)`, `GetTenantConnFromContext(c)`,
  `GetTenantLimitsFromContext(c)` still work.

Implementation: one adapter.

```go
func adapt(mw func(http.Handler) http.Handler, sync func(*gin.Context)) gin.HandlerFunc {
    return func(c *gin.Context) {
        reached := false
        h := mw(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            reached = true
            c.Request = r   // enriched context
            sync(c)         // copy context values into c.Set keys
            c.Next()        // the rest of the Gin chain runs INSIDE the core's next,
                            // so SetTenantDB's release runs after the handlers
        }))
        h.ServeHTTP(c.Writer, c.Request)
        if !reached {
            c.Abort()       // core already wrote the error response
        }
    }
}
```

The Gin `ErrorHandler` is bridged by storing `*gin.Context` in the request
context before calling the core and having the core's `ErrorHandler` closure
retrieve it. If the user set no Gin `ErrorHandler`, the core default is used.

### Nested modules and workspace

```
go.mod                       github.com/alexalmadav/go-multitenant           (no Gin)
middleware/gin/go.mod        github.com/alexalmadav/go-multitenant/middleware/gin
examples/go.mod              github.com/alexalmadav/go-multitenant/examples  (requires both; never tagged)
go.work                      use ( . ./middleware/gin ./examples )
```

The nested `go.mod`s require the core at the last published version during
development (`v0.7.1`); `go.work` resolves to the local checkout. On release,
`RELEASING.md` says: tag `v0.8.0`; bump `middleware/gin/go.mod` and
`examples/go.mod` to require `v0.8.0`; commit; tag `middleware/gin/v0.8.0`.
The examples module is never tagged. Between PR-A merging and the `v0.8.0` tag,
the Gin and examples modules build only inside the workspace (their `require`
still names `v0.7.1`, which has no `httpmw`); that window is expected and is
why the release steps bump the requires before tagging the Gin module.

Tests move with the code: the current `middleware/gin/middleware_test.go`
becomes `middleware/httpmw/middleware_test.go` (same cases, `http.Handler`
API); the Gin module gets adapter tests (context keys populated, abort
propagates, conn released after handlers run, custom ErrorHandler invoked).
Root integration tests that build a Gin router (`SetTenantDB` tests) are
rewritten on `httpmw`; the Gin module gets one integration test of
`SetTenantDB` through the adapter using the same `newTestDB` discovery
(copied helper, not shared code, to keep the modules independent).

CI: each job runs the same steps for each module via `go work`
(`go build ./...`, `go vet ./...`, `go test -short -race ./...`, and the
Postgres/PgBouncer suites for the root module and the Gin module's single
integration test). gofmt check covers the whole tree.

### Breaking (PR-A)

- Gin adapter is a separate module: add
  `require github.com/alexalmadav/go-multitenant/middleware/gin v0.8.0`.
- `RequireAdmin` and `Config.RequireAuthentication` removed.
- `MultiTenant.GinMiddleware` removed from the root struct (the root module
  cannot import Gin). `MultiTenant.HTTPMiddleware *httpmw.Middleware` added.
  Gin users call `gin.NewMiddleware(mt.Manager, mt.Resolver, mt.GetLogger(), cfg)`.

## PR-B: limits out, plan into metadata, smaller Manager

### Package `limits`

Moved from `tenant` with renames:

| was (`tenant`) | now (`limits`) |
|---|---|
| `FlexibleLimits`, `LimitValue`, `LimitType*`, `LimitSchema`, `LimitDefinition`, `DefaultLimitSchema` | same names |
| `LimitsConfig` | `Config` |
| `LimitChecker` (interface) + `NewLimitChecker` | `Checker` (interface) + `NewChecker(cfg Config, repo tenant.Repository, logger) Checker` |
| `UsageTracker` | `UsageTracker` |
| `PlanBasic/PlanPro/PlanEnterprise` and the default plan maps | `limits.ExampleConfig() Config` (basic/pro/enterprise with `UsageTables` for projects and tenant_users) |

`limits.Config` gains:

```go
// PlanOf returns the plan name for a tenant. Default: t.Plan() (metadata "plan").
PlanOf func(t *tenant.Tenant) string
```

`Checker` gains `Usage(ctx, tenantID) (map[string]int, error)`, which is
what `Manager.GetStats` used to compute. `database/postgres.NewUsageTracker`
is unchanged except its return type is `limits.UsageTracker`.

`httpmw.Middleware.EnforceLimits()` becomes
`httpmw.EnforceLimits(checker limits.Checker, errorHandler) func(http.Handler) http.Handler`
(package function, so `httpmw` only imports `limits` for this one function).
A nil checker is a pass-through. `Standard()` includes it only when the
`Middleware` was constructed with a checker (`New` gains a `WithLimits(checker)`
option). The Gin adapter mirrors this.

### Plan lives in metadata

- Remove `Tenant.PlanType`, `Context.PlanType`, `ValidatePlanType`, the
  `plan_type` column from every SELECT/INSERT/UPDATE, and the CHECK constraint
  from `CreateMasterTables`.
- Add `const tenant.PlanKey = "plan"`, `func (t *Tenant) Plan() string`, and
  `func (t *Tenant) SetPlan(plan string)`.
- `CreateMasterTables` runs, after the table statements, a one-time copy
  guarded by an `information_schema.columns` check for `plan_type`:

  ```sql
  UPDATE public.tenants
  SET metadata = metadata || jsonb_build_object('plan', plan_type)
  WHERE plan_type IS NOT NULL AND NOT (metadata ? 'plan');
  ```

  The column is not dropped. New rows never set it, so its default keeps
  legacy constraints satisfied. README tells operators to run
  `ALTER TABLE public.tenants DROP COLUMN plan_type` once nothing reads it.

### Manager and config

- `Manager` loses `CheckLimits`, `LimitChecker()`, `ValidateAccess`.
  `NewManager(config, db, repository, schemaManager, migrationMgr, logger)`.
- `Stats` becomes `{TenantID, SchemaExists, AppliedMigrations}`.
- `ResolverConfig.ValidateSubdomain func(string) error`; nil means the
  current rule (3–50 chars, `^[a-z0-9][a-z0-9-]*[a-z0-9]$`, not reserved).
  `Manager.CreateTenant/UpdateTenant` and the resolver use the same function.
- `tenant.Config` drops `Limits`. `DatabaseConfig` drops `Driver` and
  `MigrationsTable`. `tenant/interfaces.go` drops the unused `Middleware`
  and `MiddlewareFunc` types.
- Root package:

  ```go
  type Config struct {
      tenant.Config
      Limits *limits.Config // nil: no limit enforcement
  }
  func DefaultConfig() Config          // core only
  type MultiTenant struct {
      Manager        tenant.Manager
      Resolver       tenant.Resolver
      Migrations     tenant.MigrationManager
      Limits         limits.Checker      // nil when Config.Limits is nil
      HTTPMiddleware *httpmw.Middleware  // built with the checker when present
      // ...
  }
  ```

  `New` constructs the checker and the Postgres usage tracker only when
  `Config.Limits != nil`.

### Examples

`basic`: core only, no limits. `with-billing` and `flexible-limits`: use
`limits.ExampleConfig()` / custom `limits.Config`, `t.SetPlan(...)`. Plan
constants come from `limits`.

### Breaking (PR-B)

- Limits types move to `limits`; `Manager.CheckLimits`, `LimitChecker()`,
  `ValidateAccess` removed; `NewManager` signature changes.
- `Tenant.PlanType` removed; use `t.Plan()` / `t.SetPlan()`; the `plan_type`
  column is migrated into metadata and left for the operator to drop.
- `multitenant.Config` is a struct, not an alias; `Config.Limits` is a
  pointer and nil by default. `DefaultConfig()` enforces no limits.
- `Stats.Usage` removed; use `Limits.Usage(ctx, id)`.
- `DatabaseConfig.Driver`, `MigrationsTable` removed.
